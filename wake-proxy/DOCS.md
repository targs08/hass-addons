# Wake Proxy

Обратный прокси, который будит сервер при первом запросе и держит соединение,
пока сервис не поднимется.

Готовые WoL-прокси тут не подходят: машина грузится по PXE в одну из двух ОС.
Разбудить её мало — если следующая загрузка указывает на Windows, Ollama не
появится никогда. Поэтому add-on сначала переключает цель загрузки на Ubuntu,
и только потом шлёт magic packet.

## Требования

Сущности из пакета `home_server.yaml`:

- `sensor.home_server_next_boot` — куда указывает bootnext-симлинк
- `binary_sensor.home_server_windows_online` — работает ли сейчас Windows
- `shell_command.home_server_boot_ubuntu` — переключение симлинка
- `button.home_server_wake` — magic packet

Если WoL остался переключателем, укажите в `wake_entity`
`switch.home_server_wol` — будет вызван `switch.turn_on`.

Токен заводить не нужно: add-on работает через Supervisor, который выдаёт свой
токен и проксирует Core API.

## Настройки

Пример конфигурации:

```yaml
upstream_host: "192.168.178.50"
upstream_port: 11434
wake_entity: button.home_server_wake
boot_ubuntu_entity: shell_command.home_server_boot_ubuntu
next_boot_entity: sensor.home_server_next_boot
windows_entity: binary_sensor.home_server_windows_online
wake_timeout: 240
probe_interval: 3
probe_timeout: 2
boot_settle: 5
```

### Опция `upstream_host` (обязательная)

IP машины, на которой работает целевой сервис. Без неё add-on не запустится и
напишет об этом в лог.

### Опция `upstream_port`

Порт целевого сервиса. По умолчанию `11434` — порт Ollama.

### Опция `wake_entity`

Сущность, которая отправляет magic packet. Для домена `button` или
`input_button` вызывается `press`, для `switch` — `turn_on`.

### Опция `boot_ubuntu_entity`

Сущность, переключающая цель следующей загрузки на Ubuntu. Вызывается только
если `next_boot_entity` сообщает что-то отличное от `Ubuntu`.

### Опция `next_boot_entity`

Сущность, показывающая текущую цель загрузки. Значение сравнивается со строкой
`Ubuntu`.

### Опция `windows_entity`

Сущность, показывающая, работает ли машина под Windows. Если она в состоянии
`on`, add-on не будит машину и отвечает `503`.

### Опция `wake_timeout`

Сколько секунд ждать появления порта upstream после пробуждения, от 30 до 900.
Цепочка WoL → PXE → bootnext → холодный ребут → загрузка Ubuntu → старт Ollama
обычно укладывается в две минуты, но этот параметр стоит откалибровать под
своё железо.

### Опция `probe_interval`

Период опроса порта upstream в секундах, от 1 до 60.

### Опция `probe_timeout`

Таймаут одной попытки подключения к порту upstream в секундах, от 1 до 30.

### Опция `boot_settle`

Пауза после переключения симлинка загрузки, в секундах, от 0 до 60. Нужна,
чтобы magic packet не ушёл раньше, чем переключение вступит в силу.

### Опция `ha_url` (необязательная)

Адрес Home Assistant вида `http://192.168.178.100:8123`. Нужна только если
обращение через Supervisor не подходит; тогда токен передаётся переменной
окружения `HA_TOKEN`. По умолчанию используется `http://supervisor/core`.

### Опция `listen_port` (необязательная)

Порт, на котором слушает прокси, по умолчанию `11435`. При изменении нужно
поправить и проброс порта в настройках add-on'а.

## Как это работает

```
запрос → upstream доступен? ──да──► проксируем
              │нет
              ▼
     машина под Windows? ──да──► 503, будить нечего
              │нет
              ▼
   следующая загрузка не Ubuntu? → переключаем
              │
              ▼
        нажимаем кнопку пробуждения
              │
              ▼
     ждём порт upstream (до wake_timeout)
              │
              ▼
          проксируем
```

Запросы, пришедшие во время загрузки, ждут вместе: повторных пробуждений не
будет.

## Проверка

Без пробуждения:

```bash
curl http://<ip-ha>:11435/wake-proxy/health
# {"upstream": "up"} или {"upstream": "down"}
```

С пробуждением, на выключенной машине:

```bash
time curl http://<ip-ha>:11435/api/tags
```

## Клиенты

В Open WebUI и прочих клиентах вместо `http://<ip-машины>:11434` указывается
`http://<ip-ha>:11435`. Таймаут соединения у клиента нужно поднять — иначе он
отвалится раньше, чем машина загрузится.

Если прокси публикуется наружу через nginx, в его секции обязателен
`proxy_buffering off`, иначе стриминг токенов превратится в одну порцию в конце
генерации. Таймауты `proxy_read_timeout` и `proxy_send_timeout` — не меньше
`wake_timeout`.

## Ограничения

Если машина работает под Windows, add-on не станет её перезагружать и вернёт
`503`: ломать игровую сессию из-за фонового запроса неправильно. Для
осознанного переключения есть `select.home_server_boot_target`.

Засыпание по простою не реализовано — машина, однажды проснувшись, продолжит
работать.
